# Changelog

All notable changes to python-relations-redis are recorded here, newest first. Format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [SemVer](https://semver.org/).

## [Unreleased]

### Added
- `make help` lists every target with what it does (each target has a `## description` after it), and is what a bare `make` runs.
- Release tooling, the same as relations-dil's (relations-dil/python-relations#77): `make new` starts a release, `make version` sets the version, `make release-check` says where a release is up to and what would stop it, `make release` does what's left (checks, TestPyPI and a clean install from it, PyPI, the tag), `make dist-check` builds and checks the distributions, and `make test-release` tests the scripts against a throwaway repo and fake indexes. The work is in `scripts/`.

### Changed
- Every `docker run` in the `Makefile` uses `--rm`, and a replaced database container is removed with its volume (`docker rm --force -v`), so builds and test runs leave no stopped containers or volumes behind.
- `testpypi` and `pypi` run in the current `python` image with `build` and `twine` installed on the fly, so the custom `gaf3/pypi` image is no longer used.

## [0.2.4] - 2026-10-14

### Fixed
- A string id (relations-dil 0.6.18, not generated by the source) is the key of its record: `create` stores it at `<prefix>:<store>:<id>` instead of under the counter, doesn't use the counter, and refuses a repeated or missing id with a `UniqueError` before writing. Before this a string id was only in the JSON, so update failed, delete left the record behind, and the same id could be created twice.
- Reading the records of a model takes the id from the key after the prefix, so a `:` or `.` in an id is kept, and skips only the model's own counter key.
- Records sort by id with number ids first as numbers, then any others as strings, instead of failing with a `ValueError` on a string id.

## [0.2.3] - 2026-06-08

- Bumped the `relations-dil` requirement to 0.6.15 and installed git in the Dockerfile; tests were extended to cover searching ties through attributes.

## [0.2.1] - 2026-06-07

- Added a `VERSION` file read by `setup.py` and the Makefile, with an optional `BUILD_VERSION` override, to fix PyPI packaging.
- Corrected the egg-info entry in `.gitignore`; tests were extended to cover many-to-many ties.

## [0.2.0] - 2026-06-07

- Initial release of `relations_redis.Source`, a Redis Source that stores each record as a JSON string under a `<prefix>:<store>:<id>` key, with ids allocated by a per-model `INCR` counter and an optional `prefix`, `host` and `port`.
- Supported create, retrieve, count, titles, update and delete, with unique constraints checked before writes (raising `Source.UniqueError`), extracted fields stored like the mock source, and retrieve results sorted by id; filters other than id lookups are matched client-side by scanning records.
- Included a PyPI description, license, Dockerfile, Jenkinsfile, Makefile and a Redis test helper script.
